# Belong pitch

## 60 seconds

Community calendars ask people to search, scan, filter, and read a lot at once. For many people with low literacy, low vision, or intellectual disabilities, that is the barrier.

Belong replaces the calendar with a conversation. Robin asks, “What do you need today?” A person taps a large picture—food, friends, family, health, learning, or money help—then says when. Belong shows one clear opportunity card with the place, time, accessibility details, and directions. It can read every message aloud, enlarge the text, switch to high contrast, and work without typing.

For nonprofits, posting is a one-minute plain-language form. The prototype proves both required flows today. Next, a shared backend lets one listing reach Belong, nonprofit websites, and SMS without duplicate work.

It is not another better calendar. It is a friendly guide that helps more people find where they belong.

## 2.5-minute demo route

1. Start on the discovery app. Say the problem in one sentence: the current calendar presents too much information at once.
2. Turn on read aloud or high contrast to demonstrate that accessibility is part of the interaction, not a slide claim.
3. Tap **Food**, then **Anytime**. Point out the picture-supported choices, one-question-at-a-time structure, and Easy Read card.
4. Tap **I’ll go** and show the reminder step. Explain that the local counter is an aggregate engagement seed; real reminders need the planned backend/SMS service.
5. Open **For organizations**, complete the short posting form, and submit it.
6. Return to discovery and find the newly posted opportunity. Be explicit that this prototype stores it on the same device; shared multi-organization publishing is the first production step.
7. Close with the handoff: static code, no build step, clear API-shaped event data, documented gaps, and a user-testing-first continuation plan.

## Likely judge questions

**Is it really shared across nonprofits?**

The prototype validates contribution and discovery using a device-local data store. Production requires the documented shared backend, organization accounts, permissions, and moderation.

**How is this different from filters?**

It changes the cognitive task. A person answers one concrete question at a time and sees one result, rather than parsing a calendar and filter panel.

**Was it tested with users?**

Not yet. The design is grounded in established accessible-information practices, but the handoff explicitly makes co-design and usability testing the first next step.

**Why would organizations keep it updated?**

The production incentive is one short listing distributed to several channels, plus useful aggregate engagement signals. The prototype demonstrates the low-effort input format; it does not claim that distribution infrastructure is already built.
